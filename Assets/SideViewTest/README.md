# 2.5D 사이드뷰 — 공통 플레이어 기능 테스트

현재 씬 작업을 저장한 뒤 `Scenes/SideViewTest.unity`를 열고 Play → Game 창 클릭.
`SideViewPlayer` 오브젝트에는 이제 **PlayerMove 하나**가 붙습니다.

## 모드 체크

PlayerMove 인스펙터 맨 위의 **사이드뷰 모드**를 Play 전에 설정합니다.

- 켜기: 사이드뷰 전투/점프를 사용합니다. 추가로 **2.5D 바닥 8방향 이동**을 켜면 WASD가 바닥의 XY 이동이 됩니다. 테스트 프리팹에는 둘 다 켜뒀습니다.
- 끄기: 기존 WASD 탑다운 이동/방향별 전투. 세로 공격 방향 각도 설정을 표시합니다.
- HP, 대시 스태미나, 가드 게이지, 공격, 오류, 도감, 상호작용, UI 설정은 공통입니다.
- 모드 변경은 카메라/맵/Animator를 자동 변환하지 않습니다. 이 테스트 프리팹에는 사이드뷰 Animator를 연결했습니다. 탑다운에서는 기존 Player Animator/프리팹을 사용하세요.
- 기존 탑다운 프리팹의 체크박스 기본값은 꺼짐이며 수정하지 않았습니다.

2.5D 플레이어는 **본체 하나에 SpriteRenderer·Animator·PlayerMove·Collider**를 둡니다. 별도 `Visual`/`GroundMarker`는 사용하지 않습니다. Rigidbody Gravity Scale은 0으로 유지하세요.
점프하면 본체 Transform이 올라가며 `GroundPosition`은 점프 높이를 뺀 바닥 위치를 제공합니다. Collider 오프셋을 역방향으로 보정하여 바닥 충돌을 유지하고, CameraFollow·공격 판정·상호작용·오류 발견은 바닥 좌표를 사용합니다. 외부 기능에서 바닥 위치가 필요하면 `player.GroundPosition`을 사용하세요.
점프 높이는 기본 2 월드 단위이며, 착지한 상태에서 키를 새로 눌러 1회 점프합니다. 길게 눌러 자동 반복하거나 공중에서 재점프하지 않습니다. 점프 중에도 바닥 위로 이동할 수 있습니다.
이는 2.5D 이동 프로토타입입니다. 현재 전투/피격/Cut/Paste는 기존 바닥 좌표 판정을 유지합니다. 전용 한방향 발판 착지는 지원하지만 점프로 공격/일반 장애물을 회피하거나 천장에 부딪히는 높이 판정은 없습니다. 그림과 바닥 Collider는 점프 중 서로 떨어집니다.
2.5D 옵션을 끄면 기존 좌우 이동+실제 Y축 낙하/천장 충돌 방식으로 돌아갑니다. 맵/Collider는 모드에 맞게 배치해야 하며 자동 변환되지 않습니다.
공격/가드/패링/대시/물체 잡기/오류 선택·교체·Paste 준비 중에는 점프를 시작하지 않습니다. 편집 모드에서는 슬로모션 속도로 점프할 수 있습니다.
점프 높이 또는 중력을 0으로 하면 점프하지 않습니다. 점프 키는 기존 기능과 겹치지 않게 지정하세요.

## 카메라

테스트 씬의 `Main Camera`는 `GroundPosition`의 상하좌우 이동을 지연 없이 따라갑니다. 점프 높이는 따라가지 않으므로 점프할 때 화면이 들썩이지 않습니다. 기존 사용자 Offset/확대 설정은 유지했습니다.
`Main Camera → Camera Follow → Offset`으로 화면 내 위치를, Camera의 Orthographic Size로 확대 정도를 조절하세요.
테스트 씬에서는 `Use Area Bounds`를 껐으므로 맵 끝을 지나도 자유롭게 따라갑니다. 나중에 CameraBoundsArea를 배치하고 이 옵션을 켜면 구역 제한도 재사용할 수 있습니다.
다른 사이드뷰 씬에서는 카메라에 `CameraFollow`를 붙이고 Player에 해당 플레이어 Transform을 연결하면 됩니다. 탑다운 카메라 스크립트/씬은 변경하지 않았습니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| WASD / 방향키 | 바닥 8방향 이동. 대각선 속도는 직선과 같고 좌우 클립만 사용 |
| J 누르기 | 별도 높이 점프 (키/높이 인스펙터 변경 가능) |
| Space 누르기 | 스태미나를 소비하는 이동 방향 대시 |
| Space 유지 + 이동 | 대시 이후 달리기, 잔상 |
| 좌클릭 | 바라보는 방향 공격; 편집 모드에서는 공격 범위 내 오류 Cut |
| 우클릭 유지 | 가드, 피해 감소; 피격마다 가드 게이지 10 소모 |
| 공격 순간 우클릭 | 패링: 근접 경직 / 투사체 되돌리기 |
| E | 편집 모드, 슬로모션 |
| 1 / 2 | 일반 모드: 해당 슬롯 오류를 전투 기술에 적용 |
| 편집 모드에서 1 / 2 → 좌클릭 | 환경 Paste. 같은 번호 재입력은 취소, 보관함 유지 |
| 휠 → 좌클릭 | 보관함 2칸이 꽉 찼을 때 교체 선택/확정 |
| B | 발견한 오류 도감 열기/닫기 |
| F | 가까운 상자 잡기/놓기, WASD로 옮기기 |

일반 공격은 마지막 이동 방향, 편집 모드의 Cut 방향은 커서의 좌우를 사용합니다. 환경 Paste는 커서로 대상을 직접 지정합니다.
공격/가드/패링 중 이동은 잠깁니다. 공격은 마지막에서 세 번째 프레임에 판정과 이펙트를 생성합니다.
상하 이동만 할 때는 마지막 좌우 시선을 유지합니다. 공격은 좌우 방향을 유지합니다. 상호작용은 잡은 위치에서 바닥 8방향으로 물체와 함께 이동합니다.

## 테스트 배치

### 점프 발판

`Jump Test Platform`은 시작 지점 위쪽의 파란 발판입니다. 연한 사각형은 높이 0의 바닥 범위이고, 위쪽 파란 사각형은 실제 윗면입니다. 발판 기본 높이는 1, 플레이어 점프 높이는 2입니다.

1. WASD로 연한 바닥 사각형 근처에 접근합니다.
2. J + 이동으로 바닥 사각형 안에 발 위치가 오도록 점프합니다.
3. 내려올 때 높이 1에서 착지하여 파란 윗면에 섭니다. 이동 입력을 놓고 확인하세요.
4. 발판 위에서 J를 누르면 다시 점프하고, 범위 밖으로 걸어 나가면 바닥으로 떨어집니다.

아래에서는 통과 가능한 한방향 발판입니다. 그냥 걸어 들어가도 위로 올라가지 않으며, 상승 중에는 아랫면에 머리를 부딪히지 않습니다. 높이보다 낮게 점프하면 착지할 수 없습니다.
`SideViewJumpPlatform → Surface Height`로 높이, 연결된 `BoxCollider2D → Size/Offset`으로 바닥 착지 범위를 조절합니다. **Is Trigger는 켜두세요.** 그림 배치는 자동으로 범위/높이를 따릅니다. 선택 시 청록 기즈모는 바닥 범위, 노란 기즈모는 윗면입니다.
`Prefabs/JumpTestPlatform.prefab`을 복제해서 추가할 수 있습니다. 겹친 범위에서는 현재 높이 아래의 가장 높은 발판에 착지합니다. 정지 발판용이며 움직이는 발판의 탑승 이동 기능은 없습니다.

### 발판 위 연속 이동

기존 `Jump Test Platform` 오른쪽에 `Raised Walkway`와 초록색 `Raised Walkway End`를 같은 높이로 이어 붙였습니다. 입구에서 J로 한 번 올라간 뒤 D로 오른쪽 끝까지 걸어가세요. 중간에 다시 점프할 필요는 없습니다.
각 바닥 착지 범위를 조금 겹쳐 이음새에서도 떨어지지 않도록 배치했습니다. 옆으로 벗어나면 기존처럼 바닥으로 내려오며, 사망/강제 복귀는 없습니다. 초록 구간은 테스트 경로의 끝 표시이며 씬 전환/완료 이벤트는 없습니다.
통로의 길이/폭은 BoxCollider2D Size로 조절하고, 이어지는 발판의 Surface Height는 같게 맞추세요. 상단 그림만 닿게 하지 말고 연한 바닥 범위끼리도 이어져야 합니다.

### 기존 테스트 대상

- 기존 `SideView Target`: 공격 시 빨간 피격 표시와 HP 감소, 자동 회복.
- `Giant Source`, `Acceleration Source`, `Reflection Source`: 오류 원본 3종. 발견/Cut/2칸 교체 시험.
- `Moving Paste Target`: 움직이는 물체에 오류 적용 시험. 가속 시 이동 속도 변화.
- `Movable Paste Box`: F로 옮기는 물체 겸 환경 Paste 대상. 바닥 피벗이라 거대화 시 위로 확장.
- `Right Wall`: Surface 분류, 반사 Paste 가능.
- `Projectile Practice`: 4월드 단위 안에 접근하면 발사하는 공통 허수아비. 가드/패링/피격 확인용.
- 레이저 즉사/리스폰은 공통 PlayerMove API로 기존 기믹과 연결할 수 있습니다. 테스트 씬에 레이저는 추가하지 않았습니다.

도감은 이번 테스트 프리팹에서 저장하지 않고 매 실행 빈 상태로 시작합니다. 탑다운의 기존 기록을 덮어쓰지 않습니다.
현재 구현을 재사용하며, 기획서에만 있는 먹물 비용/새 튜토리얼은 추가하지 않았습니다.

## 애니메이션과 코드

플레이어 본체 선택 → Ctrl+6으로 `Animations`의 **Sprite Renderer → Sprite** 트랙을 편집합니다. 기존 프레임은 유지하고 본체 트랙으로 통합했습니다. Transform 키는 사용하지 마세요.
상태: Player_Idle / Move_Right / Jump_Right / Attack_Right / Guard_Right / Parry_Right / Interact_Idle_Right / Interact_Move_Right.
점프 클립은 `Animations/SideView_Jump_Right.anim`입니다. 플레이어 본체를 선택하고 Ctrl+6 → 해당 클립 → `Sprite Renderer → Sprite` 트랙에 프레임을 넣으세요. 스프라이트 시트는 Sprite (2D and UI)/Multiple로 잘라진 개별 Sprite 프레임을 사용합니다.
오른쪽 점프 프레임만 넣으면 왼쪽은 Flip X로 반전합니다. 점프/낙하 중 한 번 재생하고 마지막 그림을 유지하며, 착지하면 대기/이동으로 즉시 복귀합니다. 별도 낙하 클립은 없습니다.
공격/가드/패링/상호작용 애니메이션을 점프가 끊지 않습니다. 공중 공격이 끝나면 다시 점프 상태로 돌아갑니다. Jump_Right는 코드로 진입/종료하므로 Any State 전환이나 Exit Time 전환을 추가할 필요가 없습니다. Loop Time은 꺼두세요.
기존 프레임을 별도 클립으로 복사했습니다. 오른쪽 클립만 쓰며 왼쪽은 반전합니다. 원본 PNG는 공유합니다.
공통 구현은 `Assets/Scripts/Player`, 연결부는 `PlayerMove.SideView.cs`, 인스펙터는 `Internal/Editor/PlayerMoveEditor.cs`입니다.
초기 `SideViewPlayer.cs`와 `SideViewPlayer.Attack.cs`는 이전 미니 프로토타입용으로 보존했지만 현재 프리팹에는 붙이지 않습니다. PlayerMove와 동시에 붙이지 마세요.
`SideViewPracticeRoom`은 허수아비 연습 연결, `SideViewTargetDummy`는 연습 표적입니다.

기존 타이틀 시작 씬, Build Settings, 프로젝트 입력/물리 설정은 변경하지 않았습니다.
