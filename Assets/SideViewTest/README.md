# 2D 사이드뷰 — 플레이어 / 몬스터 / 보스 테스트

현재 씬 작업을 저장한 뒤 `Scenes/SideViewTest.unity`를 열고 Play → Game 창 클릭.
`SideViewPlayer` 오브젝트에는 이제 **PlayerMove 하나**가 붙습니다.

## 모드 체크

PlayerMove 인스펙터 맨 위의 **사이드뷰 모드**를 Play 전에 설정합니다.

- 현재 프리팹은 **사이드뷰 모드 ON / 2.5D 바닥 8방향 이동 OFF**입니다. A/D 좌우 이동과 실제 Y축 점프·중력을 사용합니다. W/S로 위아래를 걷지 않습니다.
- 끄기: 기존 WASD 탑다운 이동/방향별 전투. 세로 공격 방향 각도 설정을 표시합니다.
- HP, 대시 스태미나, 가드 게이지, 공격, 오류, 도감, 상호작용, UI 설정은 공통입니다.
- 모드 변경은 카메라/맵/Animator를 자동 변환하지 않습니다. 이 테스트 프리팹에는 사이드뷰 Animator를 연결했습니다. 탑다운에서는 기존 Player Animator/프리팹을 사용하세요.
- 기존 탑다운 프리팹의 체크박스 기본값은 꺼짐이며 수정하지 않았습니다.

플레이어는 본체 하나에 SpriteRenderer·Animator·PlayerMove·Collider를 유지합니다. 별도 Visual은 추가하지 않았습니다. Rigidbody Gravity Scale은 0으로 두고 공통 이동 Cast로 중력을 적용합니다.
사이드뷰 프리팹의 CapsuleCollider2D는 발밑 가로 타원 대신 몸 높이에 맞춘 세로 캡슐(0.3586×0.68)로 변경했습니다. 기존 발바닥 높이는 유지하며 Inspector에서 크기를 조정할 수 있습니다. 탑다운 플레이어의 콜라이더는 변경하지 않았습니다.
점프하면 본체와 Collider가 함께 올라가며 일반 Collider2D 바닥/천장과 충돌합니다. Space를 짧게 누르면 낮게, 상승이 끝날 때까지 누르면 최대 높이(기본 2)까지 점프합니다. 현재 2D 발판은 일반 박스이므로 아래에서 통과하는 한방향 발판은 아닙니다.
PlayerMove의 **누르는 길이에 따른 점프**가 기본으로 켜져 있습니다. **키 해제 시 상승 속도 비율**은 기본 0.45이며 낮을수록 키를 놓았을 때 빨리 상승을 멈춥니다. 이 수치는 높이 비율이 아니라 순간 상승 속도 비율입니다. **최대 점프 높이**는 길게 누른 점프 높이를 조절합니다. 체크를 끄면 기존 고정 높이 점프로 돌아갑니다.
키 해제 감속은 상승 중 한 번만 적용합니다. 떨어질 때 놓아도 낙하 속도를 바꾸지 않으며, 놓고 다시 눌러도 공중 재점프/추가 상승은 없습니다. 누른 채 착지해도 자동으로 다시 뛰지 않습니다. 추가 점프 키가 설정돼 있으면 두 키를 모두 놓아야 짧은 점프로 전환합니다. 기존 천장 충돌/착지, 점프 애니메이션, 편집 모드 슬로모션, 왼쪽 Shift 대시는 유지합니다.
기존 2.5D 옵션/SideViewJumpPlatform 코드는 보존합니다. 다시 켤 때는 2.5D용 맵 배치도 복구해야 합니다.
공격/가드/패링/대시/물체 잡기/오류 선택·교체·Paste 준비 중에는 점프를 시작하지 않습니다. 편집 모드에서는 슬로모션 속도로 점프할 수 있습니다.
점프 높이 또는 중력을 0으로 하면 점프하지 않습니다. 점프 키는 기존 기능과 겹치지 않게 지정하세요.

## 카메라

테스트 씬은 **Smooth Area Follow**를 켜서 플레이어 중심을 짧게 부드럽게 추적합니다. 이전의 방 위치 비율 매핑(Follow Across Whole Area)은 제거했습니다. 특정 게임의 카메라를 그대로 복제한 것이 아니라, 작은 움직임은 허용하고 이동하면 중심을 따라가며 방 끝에서 멈추는 방식입니다.
기본 **Follow Smooth Time = 0.12초**, **Follow Dead Zone = X 0.25 / Y 0.15**입니다. Dead Zone은 월드 단위 반경이며 작게 움직일 때 화면 흔들림을 줄입니다. 반응을 더 빠르게 하려면 Smooth Time을 낮추고, Dead Zone을 0으로 하면 미세한 움직임도 따라갑니다. 부드러운 추적을 끄면 즉시 중심 추적으로 돌아갑니다.
카메라 Size 3, Offset (0, 0, -10), 바운드 배치와 페이드는 유지합니다. 최초 배치/방 변경은 화면을 즉시 맞추며 방 변경은 암전 중 처리합니다. 같은 방에서 한 프레임에 6 이상 이동하면 리스폰/순간이동으로 보고 즉시 맞춥니다(Teleport Snap Distance).
구역 밖이 노출되지 않도록 보간 전후 위치를 제한합니다. 구역이 없으면 기존 자유 추적입니다. 작은 방/방 가장자리에서는 경계가 중심 추적보다 우선하므로 항상 플레이어가 정중앙에 있지는 않습니다. 방과 화면 크기가 같은 축은 고정됩니다. 확대나 방 크기를 자동으로 더 변경하지 않습니다.
`Main Camera → Camera Follow → Offset`으로 화면 내 위치를, Camera의 Orthographic Size로 확대 정도를 조절하세요.
테스트 씬에서는 `Use Area Bounds`와 `Fade Between Areas`를 켰습니다. 맵 구역은 직접 배치해야 합니다. 구역이 없으면 자유 추적을 유지합니다.
다른 사이드뷰 씬에서는 카메라에 `CameraFollow`를 붙이고 Player에 해당 플레이어 Transform을 연결하면 됩니다. 공통 카메라에 전환 기능을 추가했지만 탑다운의 기본 즉시 전환 방식과 씬은 유지합니다.

### 구역 배치와 암전 전환

1. `Assets/SideViewTest/Prefabs/SideViewCameraBounds.prefab`을 Hierarchy에 드래그하고 방마다 복제합니다. 또는 Hierarchy 우클릭 → **Story → Camera Bounds Area**로 만들 수 있습니다. 기본 크기는 20 × 12입니다.
2. 각 구역의 Transform 위치와 **Center / Size**(또는 Scene 사각형 핸들)를 방의 범위에 맞춥니다. Collider는 필요 없습니다. 점프할 수 있는 높이까지 포함하세요.
3. 시작 위치가 첫 구역 안에 들어가도록 하고, 이웃한 구역의 가장자리를 맞춥니다. 서로 겹치면 같은 Priority에서는 현재 구역을 유지하므로 겹친 경계를 벗어나야 전환됩니다.
4. Main Camera의 **Fade Out Duration / Black Hold Duration / Fade In Duration**으로 암전·검정 유지·밝아짐 시간을 조절합니다. 기본은 0.18 / 0.08 / 0.22초입니다.

아직 맵을 구획하지 않았다면 한 개를 전체 맵에 맞춰 바운드만 사용해도 됩니다. 페이드 확인에는 서로 다른 구역 두 개가 필요합니다. 실제 씬에 임의의 구획을 배치하지 않았습니다.

- 최초 구역에서는 바로 화면을 배치합니다. A 구역 → B 구역은 이전 카메라 정지 → 암전 → 새 경계와 줌 적용 → 밝아짐 순서입니다. 되돌아가도 동일합니다.
- 페이드는 실제 시간 기준이므로 편집 모드 슬로모션과 무관합니다. 플레이어/몬스터 이동, 전투, 게임 시간은 멈추지 않습니다. 안전한 방 입구에 경계를 배치하세요.
- 전환 화면은 CameraFollow 아래에 검정 Canvas UI로 실행 중 자동 생성됩니다. 게임 화면과 일반 Canvas UI를 가리며, 기존 임시 OnGUI HUD는 별도로 표시될 수 있습니다. 별도 이미지/Canvas 설정은 필요 없습니다.
- 경계 없는 공간에서는 Keep Last Area Outside 규칙을 따릅니다. 카메라만 제한하고 플레이어를 막는 벽이나 다른 씬 로딩은 만들지 않습니다.
- Fit Small Areas는 기존처럼 작은 방에서 줌을 맞춥니다. 캐릭터 확대를 원하지 않으면 끌 수 있지만 화면이 작은 방 밖까지 보일 수 있습니다.
- Fade Only In Side View 기본값은 켜짐입니다. 탑다운의 구역 전환은 기존 즉시 이동을 유지합니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| A/D / 좌우 방향키 | 좌우 이동. 위아래/대각선 걷기 없음 |
| Space 짧게 / 길게 누르기 | 낮은 점프 / 높은 점프 (최대 높이·해제 감속 인스펙터 변경 가능) |
| 왼쪽 Shift 누르기 | 스태미나를 소비하는 이동 방향 대시 |
| 이동 키 | 항상 기존 달리기 속도로 이동하며 잔상 표시 |
| 좌클릭 | 바라보는 방향 공격; 편집 모드에서는 공격 범위 내 오류 Cut |
| 우클릭 유지 | 가드, 피해 감소; 피격마다 가드 게이지 10 소모 |
| 공격 순간 우클릭 | 패링: 근접 경직 / 투사체 되돌리기 |
| E | 편집 모드, 슬로모션 |
| 1 / 2 | 일반 모드: 해당 슬롯 오류를 전투 기술에 적용 |
| 편집 모드에서 1 / 2 → 좌클릭 | 환경 Paste. 같은 번호 재입력은 취소, 보관함 유지 |
| 휠 → 좌클릭 | 보관함 2칸이 꽉 찼을 때 교체 선택/확정 |
| B | 발견한 오류 도감 열기/닫기 |
| F | 가까운 상자 잡기/놓기, A/D로 옮기기 |

일반 공격은 마지막 이동 방향, 편집 모드의 Cut 방향은 커서의 좌우를 사용합니다. 환경 Paste는 커서로 대상을 직접 지정합니다.
공격/가드/패링 중 이동은 잠깁니다. 공격은 마지막에서 세 번째 프레임에 판정과 이펙트를 생성합니다.
공격/가드/패링은 좌우를 사용하며 상호작용 중에도 좌우로 물체를 옮깁니다.

## 테스트 배치

### 현재 2D 전투 코스

- 시작 위치는 기존처럼 X=-6 근처입니다. 오른쪽으로 진행하면 `2D Jump Step`과 `2D Raised Walkway`에서 점프/발판 이동을 시험할 수 있습니다.
- 기존 `2D Combat Tests`의 일반 몬스터 스포너는 제거했습니다. 자동 생성은 하지 않으므로 MeleeMonster / RangedEnemy / mon_1 프리팹을 원하는 위치에 직접 배치하세요. 새 AI의 추적 모드/영역 설정은 [몬스터 안내](../Scripts/Enemies/README.md)를 참고하세요.
- X=31부터 보스 방입니다. `SideView Tutorial Boss`가 추적하고 근접/좌우 충격파/낙석을 사용합니다. 오른쪽 발판에도 낙석이 떨어집니다. 기존처럼 낙석 중 추적과 다른 공격이 가능합니다.
- 일반 몬스터 AI는 좌우 추적으로 통합했습니다. 같은 씬 플레이어가 **사이드뷰 ON / 2.5D OFF**일 때 중력도 사용합니다. 플레이어가 점프해도 날아서 따라가지 않습니다. 벽/낭떠러지 앞에서 정지하며 자동 점프·계단 오르기·발판 간 경로 탐색은 지원하지 않습니다. 보스의 모드 분기는 그대로 유지합니다.
- 원거리 적은 좌우로 접근하고, 탄환은 기존처럼 발사 순간의 플레이어 위치를 향해 발사합니다. 보스 충격파는 좌우 두 개만 발사하고 패링 이후에도 수평으로 돌아옵니다.
- 보스 `Side View Ground Layers`에 바닥/발판 레이어를 포함하세요. `Room Area / Rockfall Area`는 바닥 윗면까지 포함하는 사각형이어야 합니다. 일반 Collider2D의 윗면을 찾지 못하면 해당 낙석은 생성하지 않습니다. 경고는 바닥의 얇은 가로 표시입니다.
- 기존 2.5D `Depth Front/Back Wall`, `Jump Test Platform`, `Raised Walkway`, `Raised Walkway End`는 삭제하지 않고 비활성화했습니다. 아래는 과거 2.5D 모드를 다시 사용할 때의 참고 설명입니다.

### 이전 2.5D 점프 발판 — 현재 비활성

`Jump Test Platform`은 시작 지점 위쪽의 파란 발판입니다. 연한 사각형은 높이 0의 바닥 범위이고, 위쪽 파란 사각형은 실제 윗면입니다. 발판 기본 높이는 1, 플레이어 점프 높이는 2입니다.

1. WASD로 연한 바닥 사각형 근처에 접근합니다.
2. Space + 이동으로 바닥 사각형 안에 발 위치가 오도록 점프합니다.
3. 내려올 때 높이 1에서 착지하여 파란 윗면에 섭니다. 이동 입력을 놓고 확인하세요.
4. 발판 위에서 Space를 누르면 다시 점프하고, 범위 밖으로 걸어 나가면 바닥으로 떨어집니다.

아래에서는 통과 가능한 한방향 발판입니다. 그냥 걸어 들어가도 위로 올라가지 않으며, 상승 중에는 아랫면에 머리를 부딪히지 않습니다. 높이보다 낮게 점프하면 착지할 수 없습니다.
`SideViewJumpPlatform → Surface Height`로 높이, 연결된 `BoxCollider2D → Size/Offset`으로 바닥 착지 범위를 조절합니다. **Is Trigger는 켜두세요.** 그림 배치는 자동으로 범위/높이를 따릅니다. 선택 시 청록 기즈모는 바닥 범위, 노란 기즈모는 윗면입니다.
`Prefabs/JumpTestPlatform.prefab`을 복제해서 추가할 수 있습니다. 겹친 범위에서는 현재 높이 아래의 가장 높은 발판에 착지합니다. 정지 발판용이며 움직이는 발판의 탑승 이동 기능은 없습니다.

### 발판 위 연속 이동

기존 `Jump Test Platform` 오른쪽에 `Raised Walkway`와 초록색 `Raised Walkway End`를 같은 높이로 이어 붙였습니다. 입구에서 Space로 한 번 올라간 뒤 D로 오른쪽 끝까지 이동하세요. 중간에 다시 점프할 필요는 없습니다.
각 바닥 착지 범위를 조금 겹쳐 이음새에서도 떨어지지 않도록 배치했습니다. 옆으로 벗어나면 기존처럼 바닥으로 내려오며, 사망/강제 복귀는 없습니다. 초록 구간은 테스트 경로의 끝 표시이며 씬 전환/완료 이벤트는 없습니다.
통로의 길이/폭은 BoxCollider2D Size로 조절하고, 이어지는 발판의 Surface Height는 같게 맞추세요. 상단 그림만 닿게 하지 말고 연한 바닥 범위끼리도 이어져야 합니다.

### 기존 테스트 대상

- 기존 `SideView Target`: 공격 시 빨간 피격 표시와 HP 감소, 자동 회복.
- `Giant Source`, `Acceleration Source`, `Reflection Source`: 오류 원본 3종. 발견/Cut/2칸 교체 시험.
- `Moving Paste Target`: 움직이는 물체에 오류 적용 시험. 가속 시 이동 속도 변화.
- `Movable Paste Box`: F로 옮기는 물체 겸 환경 Paste 대상. 바닥 피벗이라 거대화 시 위로 확장.
- `Right Wall`: Surface 분류, 반사 Paste 가능.
- `Projectile Practice`: 4월드 단위 안에 접근하면 발사하는 공통 허수아비. 가드/패링/피격 확인용.
- 레이저 즉사/리스폰은 공통 PlayerMove API로 기존 기믹과 연결할 수 있습니다. 테스트 씬에 레이저는 추가하지 않았습니다.

도감은 이번 테스트 프리팹에서 저장하지 않고 매 실행 빈 상태로 시작합니다. 탑다운의 기존 기록을 덮어쓰지 않습니다.
현재 구현을 재사용하며, 기획서에만 있는 먹물 비용/새 튜토리얼은 추가하지 않았습니다.

## 애니메이션과 코드

플레이어 본체 선택 → Ctrl+6으로 `Animations`의 **Sprite Renderer → Sprite** 트랙을 편집합니다. 기존 프레임은 유지하고 본체 트랙으로 통합했습니다. Transform 키는 사용하지 마세요.
상태: Player_Idle / Move_Right / Jump_Right / Attack_Right / Guard_Right / Parry_Right / Interact_Idle_Right / Interact_Move_Right.
점프 클립은 `Animations/SideView_Jump_Right.anim`입니다. 플레이어 본체를 선택하고 Ctrl+6 → 해당 클립 → `Sprite Renderer → Sprite` 트랙에 프레임을 넣으세요. 스프라이트 시트는 Sprite (2D and UI)/Multiple로 잘라진 개별 Sprite 프레임을 사용합니다.
오른쪽 점프 프레임만 넣으면 왼쪽은 Flip X로 반전합니다. 점프/낙하 중 한 번 재생하고 마지막 그림을 유지하며, 착지하면 대기/이동으로 즉시 복귀합니다. 별도 낙하 클립은 없습니다.
공격/가드/패링/상호작용 애니메이션을 점프가 끊지 않습니다. 공중 공격이 끝나면 다시 점프 상태로 돌아갑니다. Jump_Right는 코드로 진입/종료하므로 Any State 전환이나 Exit Time 전환을 추가할 필요가 없습니다. Loop Time은 꺼두세요.
기존 프레임을 별도 클립으로 복사했습니다. 오른쪽 클립만 쓰며 왼쪽은 반전합니다. 원본 PNG는 공유합니다.
공통 구현은 `Assets/Scripts/Player`, 연결부는 `PlayerMove.SideView.cs`, 인스펙터는 `Internal/Editor/PlayerMoveEditor.cs`입니다.
초기 `SideViewPlayer.cs`와 `SideViewPlayer.Attack.cs`는 이전 미니 프로토타입용으로 보존했지만 현재 프리팹에는 붙이지 않습니다. PlayerMove와 동시에 붙이지 마세요.
`SideViewPracticeRoom`은 허수아비 연습 연결, `SideViewTargetDummy`는 연습 표적입니다.

기존 타이틀 시작 씬, Build Settings, 프로젝트 입력/물리 설정은 변경하지 않았습니다.
